# IP_CHANGER — FULL DEVELOPMENT SPECIFICATION

## 1. PROJECT OVERVIEW

Develop a professional Windows desktop application called **IP_CHANGER**.

The application must provide a very simple and reliable GUI for configuring network adapters.

The main purpose is to allow an operator/technician to:

* View all available network adapters.
* Select a network adapter.
* View its current IP configuration.
* Change:

  * IPv4 address
  * Subnet mask
  * Default gateway
* Switch between DHCP and Static IP.
* Save named IP configurations/presets.
* View previously saved configurations.
* Apply a saved configuration with one click.
* Validate configurations before applying them.
* Clearly show the current active configuration.
* Recover gracefully from errors.
* Always request/elevate Administrator privileges when required.

The application must be designed primarily for **industrial/commissioning environments**, where reliability and simplicity are more important than having many unnecessary features.

The operator should be able to configure an adapter in a few seconds without needing to understand Windows networking commands.

---

# 2. TARGET PLATFORM

Primary target:

**Windows 10 and Windows 11 — 64 bit**

The application must work on standard Windows installations without requiring the user to manually install Python or additional dependencies.

The final application should preferably be distributable as:

`IP_CHANGER.exe`

or as a small installer producing:

`IP_CHANGER.exe`

The application must run with Administrator privileges when required.

---

# 3. CORE DESIGN PRINCIPLE

DO NOT implement this as a simple GUI that blindly executes shell commands.

The application must have a robust architecture with:

### GUI layer

Responsible for:

* User interaction
* Display
* Validation feedback
* Preset management
* Status
* Confirmation dialogs

### Network management layer

Responsible for:

* Enumerating adapters
* Reading adapter configuration
* Validating configuration
* Applying configuration
* Verifying the result

### Privileged execution layer

All operations requiring Administrator privileges must be executed through a controlled privileged mechanism.

Do not give unnecessary privileges to unrelated components.

The application must detect whether it is running elevated.

If not elevated, restart itself with Administrator privileges using the standard Windows UAC mechanism.

* Python 3.12+

# 8. CURRENT CONFIGURATION

* Subnet mask / prefix
* Gateway

### DHCP

* Enabled / Disabled

### DNS

# 9. DHCP MODE

Provide a clear toggle:

```text
DHCP
○
```

When DHCP is selected:

* IP fields become disabled.
* Subnet field becomes disabled.
* Gateway field becomes disabled.
* Applying configuration switches the adapter to DHCP.

After applying DHCP:

1. Wait for Windows to configure the adapter.
2. Refresh the adapter.
3. Read the resulting configuration.
4. Display the obtained IP address.
5. Verify the adapter state.

Do not simply assume that the DHCP operation succeeded.


# 11. INPUT VALIDATION

Validation must happen BEFORE any system modification.

Validate:

### IPv4

Must be a valid IPv4 address.

Examples:

Valid:

```text
192.168.1.100
10.0.0.10
172.16.10.50
```

Invalid:

```text
192.168.1.999
192.168.1
hello
```

### Subnet mask

Validate both:

* Traditional subnet masks:
  `255.255.255.0`

* If the implementation uses CIDR internally:
  `/24`

The GUI should preferably display traditional subnet notation.

### Gateway

Must be a valid IPv4 address.

Validate logical consistency.

Example:

```text
IP:
192.168.1.100

Mask:
255.255.255.0

Gateway:
192.168.2.1
```

should trigger:

```text
Gateway appears to be outside the configured subnet.
Continue anyway?
```

Do not automatically block unusual configurations unless they are objectively invalid.

# 12. SPECIAL CASES

The application must correctly handle:

* 169.254.x.x APIPA addresses
* No IP address
* Multiple IPv4 addresses
* Disabled adapter
* Disconnected Ethernet
* Wi-Fi adapter
* Virtual adapters
* VPN adapters
* Hyper-V adapters
* VMware adapters
* Docker adapters
* Loopback adapters

Do not blindly treat every adapter as a physical Ethernet interface.

Provide a way to identify adapter type.

For example:

```text
Ethernet
Physical
```

versus:

```text
vEthernet (Default Switch)
Virtual
```

The user should still be able to configure supported adapters, but the application must make their nature clear.

# 13. APPLY CONFIGURATION

This is the most critical functionality.

When the user clicks:

```text
APPLY CONFIGURATION
```

the application must NOT immediately modify the adapter.

First perform:

### Step 1 — Validate

Check:

* IP
* subnet
* gateway
* consistency
* duplicate/obvious conflicts where detectable

### Step 2 — Show confirmation

Example:

```text
Apply network configuration?

Adapter:
Ethernet

Current:
192.168.1.100 / 255.255.255.0
Gateway: 192.168.1.1

New:
192.168.10.50 / 255.255.255.0
Gateway: 192.168.10.1

The network connection may be temporarily interrupted.

[ CANCEL ]    [ APPLY ]
```

### Step 3 — Create a rollback snapshot

Before modifying anything, save the current configuration in memory.

### Step 4 — Apply

Perform the configuration change.

### Step 5 — Wait

Allow Windows time to update the network stack.

### Step 6 — Refresh

Re-read the adapter.

### Step 7 — Verify

Compare actual configuration against requested configuration.

### Step 8 — Report result

Success:

```text
✓ Configuration applied successfully

Ethernet
192.168.10.50
255.255.255.0
192.168.10.1
```

Failure:

```text
✕ Configuration could not be verified.

The previous configuration can be restored.

[ RESTORE PREVIOUS CONFIGURATION ]
```

---

# 14. ROLLBACK

Rollback is mandatory.

If configuration fails or verification fails, the application must be able to restore the previous configuration.

Before every modification capture:

* DHCP state
* IPv4 address(es)
* subnet
* gateway
* interface index/name
* relevant configuration required to restore the state

If multiple IPv4 addresses are configured, rollback must restore the complete previous state, not only the first address.

The rollback operation must be independently executable.

Provide:

```text
RESTORE PREVIOUS CONFIGURATION
```

after a failed operation.

```text
Make sure you have physical/local access to the computer
```

# 19. APPLY PRESET

When applying a preset:

1. Verify that the target adapter exists.
2. If possible, match using stable adapter identity.
3. Show the configuration.
4. Validate it.
5. Ask confirmation.
6. Save current configuration.
7. Apply preset.
8. Verify.
9. Report success/failure.

If the adapter no longer exists:

```text
Adapter not found.

This configuration was saved for:
Ethernet
MAC: XX:XX:XX:XX:XX:XX

Please select another adapter or edit the preset.
```

Never silently apply a preset to a different adapter.

---

# 20. DUPLICATE IP WARNING

Where technically feasible, implement a duplicate-IP check.

After applying a static IP, optionally perform a basic network conflict detection.

However:

DO NOT rely on ping alone as proof that an IP is free.

A device may block ICMP.

Therefore the application should report:

```text
IP conflict check:
No conflict detected
```

or:

```text
IP conflict check:
Unable to determine
```

rather than falsely claiming the address is definitely free.

---

# 21. ADMINISTRATOR PRIVILEGES

The application must correctly handle Windows UAC.

At startup:

1. Detect whether running elevated.
2. If not elevated:

   * restart itself with Administrator privileges.
3. Preserve application arguments/state when restarting.

The GUI should display:

```text
● Administrator
```

or:

```text
⚠ Administrator privileges required
```

depending on state.

Never ask the user to manually open CMD as Administrator.

The application itself must handle elevation.

# 22. ERROR HANDLING

The application must never crash because:

* Adapter disappears
* Cable is unplugged
* Wi-Fi disconnects
* Windows returns an error
* Invalid configuration is entered
* PowerShell fails
* API call fails
* Network stack is temporarily unavailable
* User cancels UAC
* Database cannot be accessed

All errors must be caught and translated into understandable messages.

Do not expose raw stack traces to normal users.

Example:

BAD:

```text
subprocess.CalledProcessError: Command returned non-zero exit status 1
```

GOOD:

```text
Unable to change the network configuration.

Windows rejected the requested configuration.

Details:
The gateway address is not valid for this interface.
```

A technical details expandable section can be available for engineers.

# 29. WINDOWS IMPLEMENTATION

Investigate and choose the most reliable Windows-native mechanism.

Priority:

1. Windows networking APIs
2. CIM/WMI where appropriate
3. PowerShell
4. netsh only where required

Avoid fragile assumptions about command output.

If a command-line tool is required:

* Use subprocess safely.
* Never use shell=True unless absolutely necessary.
* Pass arguments as lists.
* Capture stdout/stderr.
* Validate exit codes.
* Implement timeout.
* Log failures.

# 30. SUBNET HANDLING

Internally normalize network configurations.

For example:

```text
255.255.255.0
```

should internally correspond to:

```text
/24
```

Use Python's `ipaddress` module.

Example:

```python
ipaddress.IPv4Address(...)
ipaddress.IPv4Network(...)
```

Do not implement custom IP parsing.

# 54. RECOVERY AFTER APPLICATION CRASH

Where practical, maintain the last configuration snapshot.

If the application crashes immediately after changing the configuration, reopening the application should detect the previous incomplete operation.

Display:

```text
Previous network operation did not complete successfully.

The last operation involved:

Adapter: Ethernet
Previous IP: 192.168.1.100
Requested IP: 192.168.10.100

[ CHECK CURRENT CONFIGURATION ]
[ RESTORE PREVIOUS CONFIGURATION ]
```

Do not automatically rollback after application restart without user confirmation.

```text

 ↓

 ↓
VALIDATE
 ↓
CONFIRM
 ↓
APPLY
 ↓
WAIT
 ↓
VERIFY
 ↓
SUCCESS
```

If:

```text

 ↓
FAIL
```

then:

```text
ROLLBACK
 ↓
VERIFY ROLLBACK
```

If rollback itself fails, clearly report this.
